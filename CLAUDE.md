# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

"Bombe și Petarde" — browser multiplayer bomb-arena game with a Romanian New Year's theme. npm workspaces monorepo: `shared/` (pure game logic), `client/` (Phaser 3 + Vite), `server/` (authoritative Colyseus server). README and user-facing strings are in Romanian; code comments are in English. Requires Node ≥ 22.12.

## Commands

Run from the repo root:

```bash
npm install
npm run dev          # client (http://localhost:5173) + server (:2567) together; dev:client / dev:server for one
npm test             # vitest for /shared, then the server room tests (@colyseus/testing)
npm run typecheck    # tsc for shared + client + server
npm run build        # client/dist (static) + server/dist/index.js (single esbuild bundle)
npm run og           # regenerate client/public/og.png + favicons from client/assets-src/icons.mjs (resvg)
```

Single test file / test name:

```bash
npm test -w shared -- test/explosions.test.ts
npm test -w shared -- -t "<test name substring>"
npm run test:watch -w shared
npm test -w server -- -t "<test name substring>"   # boots a real server on :2568
```

Test URL options: `?debug`, `?bots=1..5` (default 3), `?rounds=3|5|7`, `?seed=abc`. Any of them skips intro/menu/lobby and starts a local match at once (`quick` mode: `Enter` after the match restarts immediately). `?touch` / `?touch=0` force the phone layout and touch controls on or off (otherwise `(hover: none) and (pointer: coarse)`, see `client/src/device.ts`). `?debug` overlays grid coordinates, hitboxes, danger zones, tick/FPS and each bot's intent + planned path. `?room=COD` is the invite link: intro, then a nickname-only menu that joins. In-game: `P` pauses (local only).

`VITE_SERVER_URL` defaults to `/colyseus` (same host: the Vite proxy in dev, Caddy in production); set it empty for an offline-only build. The Vite dev server listens on all interfaces (`host: true`) so a phone on the same Wi-Fi can open `http://<LAN IP>:5173`.

## Architecture

### `/shared` — deterministic simulation (no Phaser, no DOM)
- Consumed as raw TypeScript (`main`/`exports` point at `src/index.ts`); no build step.
- **Determinism is a hard rule**: never use `Date.now()` or `Math.random()` in shared code. Randomness goes through the seeded mulberry32 RNG whose state lives inside `GameState` (`rng.ts`). Same seed + same inputs must yield the same state (`test/determinism.test.ts`).
- `GameState` is intentionally flat (grid as `number[]`, players as `Record<id, PlayerState>`, bombs/flames/powerups as arrays) so it maps directly onto `@colyseus/schema` (`server/src/schema.ts` + `mirror.ts`). Keep it that way; a new `GameState`/`PlayerState` field must be added to the schema, the mirror key lists and `toGameState` in `ColyseusTransport`.
- The only way players affect the game is `applyInput(state, { playerId, action })`: direction is held until changed; a bomb press is latched and consumed on the next tick. `step(state)` advances one fixed tick (20/s, `TICK_MS`) and returns `GameEvent[]` used by the client for sound/effects.
- `match.ts` owns lobby/round/match lifecycle (`createGameState`, `addPlayer`, `addBot`, `startMatch`, `backToLobby`, `leavePlayer`, standings). `leavePlayer` is a permanent leave: removed in the lobby, mid-match the player dies without crediting a kill and stays (`left`) in the standings until the lobby; the host passes to the next connected human, never a bot. A round's map is generated by `prepareRound` when the intermission *starts* (so the client can show it dimmed between rounds); `startRound` only resets players/timers on that map; `sim.ts` owns per-tick rules, including the round-start countdown (`COUNTDOWN_TICKS`, "3, 2, 1, FOC!": nobody moves and bomb presses are dropped until FOC; `SHRINK_START_TICKS` includes it so the two minutes of fighting stay intact; `countdownSeconds` for the display); `PlayerState` also carries match statistics for the awards (`suicides`, `bricks`, `pickups`, reset by `startMatch`, never used for scoring) and `awards.ts` turns them into `computeAwards`; `shrink.ts` the spiral arena shrink; `bot.ts` has `botDecide` and `botThink` (same decision plus intent and planned path, used by the debug overlay).
- `runner.ts` is the one tick every host runs (`runTick`: queued inputs, bot decisions, `step`) plus `skipBotRound`; `LocalTransport` and the server room both use it. `protocol.ts` is the wire contract (`ClientMessage`, the `events` message with its tick, error codes, `RoomStatus`).
- Tests build states from ASCII maps via `makeState` in `test/helpers.ts` (`#` wall, `+` brick, `.` empty, `1`..`6` players `p1`..`p6`).

### `/client` — rendering only
- Scene flow (wired in `main.ts` with `scene.add`): `intro` → `name` → `menu` → `lobby` ⇄ `game`. A `?room=` invite is carried through and the menu joins it at once; a tab reload during an online game skips straight to the menu with `resume`, unless the `?room=` link points to another room: then the menu gets `switchFrom` and asks before leaving the current game for good (`abandonResumableRoom`) and joining the link's room. The reconnection token is stored with its room code. Lobby and game hand the same transport back and forth by watching `state.phase` (`lobby` vs anything else); only leaving ("Ieși din joc" in the lobby, "Ieși" with confirmation in the game) disposes it: a consented leave that also forgets the reconnection token. Both scenes call `notifyPresence` (`ui/presence.ts`) every frame, which diffs player snapshots per transport into join/leave/drop/back/new-host toasts. Phaser reuses scene instances, so per-match fields are reset in `init()`.
- **HTML over the canvas**: intro, name, menu and lobby are HTML screens (`mountScreen` in `ui/dom.ts`: appended in `create()`, removed on the scene's SHUTDOWN, responsive CSS in `client/src/style.css`); their Phaser scene only draws the sky (`ui/backdrop.ts`) with the scale mode switched to ENVELOP (`useScaleMode`; the game switches back to FIT). The game itself stays in Phaser. Always-on HTML layers: `ui/chrome.ts` (mute/fullscreen icons, `F`), `ui/Toasts.ts` (`showToast(opts)`, reusable for any message), `ui/ConnectionBanner.ts`, `ui/orientation.ts` (the "Rotește telefonul" prompt over scenes that call `requireLandscape`), `ui/dialog.ts` (modals; `ui/settingsDialog.ts` is "Setări"), `ui/installHint.ts` (iPhone: add to home screen). `isTyping()` and `onKey()` in `ui/dom.ts` keep shortcuts out of text fields and focused buttons. `ui/CodeInput.ts` is the six-box room code field (plain DOM). The canvas parent `#stage` sits inside `#game`, which is padded by the safe-area insets (not behind the HTML screens). `localStorage` goes through `client/src/storage.ts` (keys prefixed `petarde.`, failures ignored).
- The menu gets rooms from `client/src/net/rooms.ts`: `createRoom` / `joinRoom` go online (or `createRoom` falls back to local in an offline-only build), `createOfflineRoom` is "Joacă offline cu boți", `resumeRoom` reconnects after a tab reload (token in `sessionStorage`). Failures are `RoomError`s with Romanian messages; `offline: true` makes the menu offer the offline game right under the message.
- **Phones and tablets** (`isTouch` in `device.ts`, decided once at startup): `render/layout.ts` then uses a wider canvas (`GAME_W` = board + a `SIDE_W` thumb zone on each side) so the controls never cover the arena; `GameScene.createTouchHud` puts round info and a one-line player list on one side and thumb-sized buttons (Ieși / Clasament toggle / Pauză) on the other, mirrored by "Mod stângaci". `settings.ts` holds the per-device toggles (reduced effects, on by default on touch; joystick; left-handed; vibration). `device-apis.ts` has the Screen Wake Lock (`keepScreenOn(scene)`, lobby and game) and `vibrate`. `ui/fullscreen.ts` fullscreens the whole document (HTML layers included) and, on phones, arms "fullscreen on the next tap" in the lobby and the game. When the page is hidden the game scene releases held input (sends `stop`) and pauses offline games; `ColyseusTransport` drops events older than 2 s instead of replaying them at once.
- Optional audio goes through `client/src/audio/sound.ts`: files are fetched and decoded manually (the Phaser loader logs errors for missing files), and mute state is tracked there because WebAudio's `sound.mute` getter lags after being set. Sound effects are `audio/sfx.ts`: each `SFX_NAMES` entry is synthesized with Web Audio unless `public/audio/<name>.ogg|.mp3` exists (looked up once by `initSfx`); keep the README's sound table in sync with `SFX_NAMES`.
- Scenes never touch the simulation directly; they read state and send messages only through the `GameTransport` interface (`client/src/net/GameTransport.ts`). `LocalTransport` runs the shared simulation in-browser with bots and a fixed-step accumulator. `ColyseusTransport` rebuilds a plain `GameState` from the decoded schema and queues `events` messages until the state reaches their tick (patch and message may arrive in either order), so effects line up with the drawing. `connectionStatus()` drives `ui/ConnectionBanner` ("Se reconectează..." in lobby/game; back to the menu once closed).
- The `skipRound` message fast-forwards a round once `onlyBotsAlive(state)` and reports only `roundEnd`/`matchEnd`. **Only the host may send it, and only when every human player is dead**; the scene shows it only then and the server enforces it.
- Input comes from an `InputSource` (`client/src/input`), polled once per frame: `KeyboardInput` (arrows/WASD + Space) and, on touch devices, `TouchInput` (HTML D-pad or joystick + petard button, pointer events per finger, direction from the angle to the pad's center) combined with the keyboard by `CombinedInput`.
- Players are interpolated between the last two ticks. All textures are generated procedurally at startup (`render/textures.ts`); there are no image assets. Particle bursts go through `render/fx.ts` (`burst`, `firework`), which enforces a global particle cap; snow (`addSnow`) and the "Efecte reduse" setting (`client/src/settings.ts`, toggled in the menu or under "Setări" on touch devices) live there too. HTML parts reuse baked textures through `textureUrl(game, key)` (lobby avatars, the petard button). The final screen is `ui/Podium.ts`; the Tab overlay and the final table share `ui/StandingsTable.ts`.

### `/server` — authoritative Colyseus 0.18 room
- `@colyseus/core` + `ws-transport` + `schema` 5 (not the `colyseus` meta-package); the client uses `@colyseus/sdk`. Details and deploy steps in `server/README.md`.
- `BombeRoom` (room name `bombe`): the 6-char code is the `roomId` (clients `joinById(code)`), `MAX_ROOMS` cap in `onCreate`, `lock()` at Start / `unlock()` back in the lobby. Every tick: `runTick` → `mirror()` into the schema → broadcast `{ tick, events }`. Events produced outside a tick (leaves, skips) go out with the next one.
- All validation is server-side: player id from the connection, inputs only while playing (30/s, extra ignored; >60 msgs/s disconnects), host-only lobby actions via the `/shared` functions. `onDrop` keeps the seat 15 s; `onLeave` = `leavePlayer`.
- `GET /health`, and `GET /rooms/:code` because Colyseus reports a full room and a running match the same way ("locked").
- Production: `node dist/index.js` (esbuild bundle with `/shared` and all deps, no `node_modules`), loopback only, `PORT`/`MAX_ROOMS` from env. The SDK keeps the `/colyseus` path prefix as long as the server never sets `publicAddress`.

### `/deploy` — Oracle VPS (Ubuntu, SSH alias `oracle`, https://bombe-petarde.duckdns.org)
- `setup.sh` (first install on the VPS, idempotent), `push.ps1` (Windows: test/typecheck/build, tar.gz upload, `-WhatIf`, `-Rollback`), `remote-update.sh` (server side of push: releases under `/opt/bombe/releases`, atomic `current`/`current.prev` symlink switch, health check with automatic rollback), `bombe.service`, `Caddyfile` block.
- The VPS also hosts the train game (`cabina-api`, `/var/www/cabina`, `tren-api.duckdns.org`): never touch it. Never run anything on the VPS from here; only prepare and dry-run (`push.ps1 -WhatIf`).
